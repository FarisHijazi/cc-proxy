# Renew a login Anthropic rejected before it expired

From 14:59:57 to 15:36:11 EST on 2026-11-09, every non-inference request using the main login through the shared proxy returned 401. This covered artifacts, Remote Control presence, skills, connectors and event logging. Claude inference kept working only because the pool fell back to another account, so clients saw the proxy appear to switch accounts and artifact publishing fail with HTTP 401.

The traffic database showed the token was rejected while it was locally unexpired. No OAuth or login request went through the proxy at the start of the window. cswap documents this case: a sibling machine rotating a synced lineage can revoke the previous access token before `expiresAt`. The proxy's cache kept the token until its expiry margin. By design, `slot_token` never refreshes the live login, so recovery waited until a Claude process on the proxy host refreshed `~/.claude/.credentials.json`.

Change: `account_inject.responseheaders` notices a 401 on a token it injected, recorded as `flow.metadata["account_login"]` on the non-pool path. `rejected` drops that cache entry only if it still holds the sent token. It then starts `renew_rejected` in a background thread, at most once per `RENEW_EVERY_S` per account. `renew_rejected` acts only when cswap still holds the rejected token. For the live login it calls cswap's `_fetch_active_usage`, which re-probes and refreshes under Claude Code's own lock protocol, so a running claude adopts the result. For a backup slot it calls `consume_backup_grant`. The proxy contains no refresh logic of its own. Inference requests rely on the router's existing 401 quarantine; the same cache eviction also fixes the pool's next token.

Verification: three new tests in `tests/account_inject_test.py` cover a burst of 401s renewing once, a 401 for a token that has already been replaced, and cswap acting only on the rejected credential. The inject suite passed 47 tests, and the full Python suite passed apart from two router tests. Those two fail only when `claude-swap` is installed in the test environment, with or without this change. All 56 router tests pass without it. Deployed to the shared proxy with a backup in `~/.local/state/claude-codex/before-401-renew-20261109/`. After the restart, the main login served 20 non-inference requests with 200 in one minute, and answered inference itself. The revocation path itself was not reproduced live, because that would require revoking a real token.
